Setting up the guest album

Ten steps, about half an hour, plus a rehearsal with two phones. Nothing here needs code — it is all clicking through Google, with two values pasted into files at the end.

  • The RSVP spreadsheet
  • Google Drive
  • This repo, on your machine
  • Two phones, for step 10
Two things here are called "deploy"

Step 5 deploys the Apps Script as a Web app — that is the album's backend, the thing that receives photos and writes them to Drive. Step 8 publishes the website on GitHub Pages, so guests have a page to open. Different services, unrelated buttons. The only thread between them is one URL you copy from the first into the second.

  1. Add the Config tab

    In the RSVP spreadsheet

    This tab is the album's control panel. Everything about when it opens and closes lives here, and editing it never needs a redeploy.

    First: File → Settings → Time zone → (GMT+08:00) Manila. Then add a new tab named exactly Config and fill it in:

    A — SettingB — ValueWhat it does
    open_at2026-11-11 13:00uploads open at this moment, venue time
    close_atleave blankuploads stop; blank means never
    force_openFALSETRUE overrides both dates — open right now
    admin_keya long secret you inventunlocks hiding photos

    Row 1 can be a header (Setting / Value) — it is skipped either way.

    Before you type the date

    Select cell B2 and set Format → Number → Plain text. Sheets otherwise converts 2026-11-11 13:00 into a date value, which still works — but only if the spreadsheet's time zone is Manila. Plain text takes that dependency away.

    Pick the admin_key like a password: long, random, not a word. It does two things — it puts the hide button on your phone, and it lets you post before 1:00 PM. Anyone who has it can do both.

    Do not create a Photos tab. The script writes that one itself on the first upload.

  2. Make the Drive folder

    In Google Drive

    Create a folder for the photos — JG Guest Album is a fine name. Open it and read the ID out of the address bar:

    drive.google.com/drive/folders/1AbC…xyz
                               └─────┬─────┘
                                 FOLDER_ID

    Keep it somewhere for a moment; step 4 needs it.

  3. Copy the spreadsheet ID

    In the RSVP spreadsheet

    docs.google.com/spreadsheets/d/1XyZ…abc/edit
                               └────┬────┘
                                 SHEET_ID

  4. Create the script

    script.new

    Go to script.new, name the project JG Guest Album, delete the stub function, and paste in the whole of google-apps-script/photos.gs.

    Fill in the two lines near the top:

    var SHEET_ID  = "1XyZ…abc";
var FOLDER_ID = "1AbC…xyz";

    Then gear icon → Project Settings → Time zone → (GMT+08:00) Manila, and save.

    A separate project, not the RSVP one

    An Apps Script project can only define one doGet, and more to the point: a bug in photo code on the wedding day must not be able to take the RSVP down with it.

  5. Deploy it as a Web app

    In the script editor

    You are deploying the whole script project. There is no file or function to pick — Google calls doGet and doPost itself whenever a browser hits the URL.

    1. Blue Deploy button, top right → New deployment
    2. In the dialog, click the gear labelled Select type
    3. From the list — Web app · API Executable · Add-on · Library — choose Web app
    4. Execute as: Me
    5. Who has access: Anyone
    6. Deploy

    "Anyone" — not "Anyone with a Google account". Guests scanning a card at a reception will not be signed in.

    If "Web app" isn't in the list

    The type only appears once the project contains a doGet, so photos.gs did not paste in completely. Check the file is all there, save, and reopen the dialog.

    Google will ask you to authorize, then warn that it hasn't verified the app. That is expected for a script you wrote: Advanced → Go to JG Guest Album (unsafe) → Allow.

    Copy the Web app URL. It ends in /exec.

  6. Prove the deployment works

    In any browser tab

    Do this before touching the website. Paste the /exec URL straight into the address bar. You should get JSON:

    {"ok":true,"open":false,"admin":false,
 "opensAt":"2026-11-11T13:00:00+08:00",
 "closesAt":null,"now":"2026-08-05T…+08:00"}

    Then add ?action=list to the same URL. Expect {"ok":true,…,"photos":[]}.

    Check the time reads right

    opensAt must say 13:00 and +08:00. If it says 05:00, the time zone is wrong — go back to step 4.

    If you get "ok":false

    Read the detail field.

    If it mentions formatDate, a pattern, or XXX — stop and tell me. The timestamp format is the one thing in the backend I could not test without a live deployment, and if your runtime rejects it, every request fails and the album stays permanently offline. It is a one-line fix, but nothing works until it is made.

    If it mentions permission or not found, one of the two IDs in step 4 is wrong.

  7. Point the site at the script

    js/shareApi.js, line 12

    var ENDPOINT = "https://script.google.com/macros/s/AKfyc…/exec";

    Commit and push.

  8. Publish the site

    On GitHub

    If Pages isn't on yet: repo → Settings → Pages → Deploy from a branch → main / (root). The album will be at:

    https://juriel09.github.io/juriel-grace-wedding/share.html

    Open it on a phone. You should see "The guest album opens soon" with a live countdown ticking down to 1:00 PM on 11 November. That is the whole front end working — the gate is being read from your sheet.

  9. Make the QR and the table cards

    In the repo

    npm run qr -- --url https://juriel09.github.io/juriel-grace-wedding/share.html

    That writes media/qr/share-qr.svg and media/qr/table-card.html. Open the card and print it to 5×7 — it is already laid out for that size, in the invitation's paper and gold.

    Scan the printed card, not the screen

    Paper, ink density and the card's border are what actually decide whether a phone reads the code across a dim reception table. A QR that scans perfectly on a monitor can fail on card stock.

    The URL is final once these are printed

    Be sure of the address before the print run. A printed card cannot be edited, and there is no redirect behind it.

  10. Rehearse it, with two phones

    Anywhere, about ten minutes

    Set force_open to TRUE in the Config tab and wait twenty seconds — that is how long the script caches config.

    1. Phone A opens the album page. It shows "Share your photos", not the countdown.
    2. Phone A adds two photos, one of them shot in portrait. Both appear at the top of the wall straight away, the right way up.
    3. Phone B opens the album page. Phone A's photos appear within about twenty seconds.
    4. Phone B tries to add a video. It is refused with "photos only, please" and nothing is uploaded.
    5. Your phone opens …/share.html?key=YOUR_ADMIN_KEY. A ✕ appears on every tile. Hide one — it goes immediately on your phone, and disappears from Phone A and Phone B within about twenty seconds.
    6. Drive holds files named like Guest-1247_20261111-134512-702.jpg, plus a _hidden folder containing the one you hid.
    7. The sheet has a new Photos tab: one row per upload, with TRUE in the Hidden column for that photo.
    8. Set force_open back to FALSE. Within twenty seconds both phones fall back to the countdown.

    Step 5 is the one to watch. Until recently hiding a photo only cleared it from the phone that tapped ✕ — every other guest kept seeing it. If it vanishes from all three phones, the moderation actually works.

On the day

Nothing to do. open_at opens the album at 1:00 PM by itself, and any phone already sitting on the countdown flips over without a refresh. If you want it open earlier, set force_open to TRUE; to close it, put a time in close_at. Config changes land within twenty seconds and never need a redeploy.

If you edit photos.gs later

Deploy → Manage deployments → pencil → Version: New version → Deploy. The /exec URL stays the same.

Do not use "New deployment" for an update. That mints a different URL, and every printed card would still be pointing at the old one.

Keep the admin key secret

It unlocks hiding and bypasses the opening time. Never put it on the card, in the QR, or in a link you send to a group. If it gets out, change the cell — it takes effect in twenty seconds.

What the album will and won't do

  • Ten photos per pick, as many picks as a guest likes
  • Sixty uploads per phone per hour
  • Photos are shrunk to 2400px in the browser before sending — about 1MB each, still large enough to print
  • iPhone HEIC arrives as JPEG, openable on anything
  • Videos are refused at three separate layers
  • The wall shows the newest 300 photos; everything ever sent stays in Drive
  • Uploaders are anonymous — each phone gets a tag like Guest-1247 that groups its files in Drive and is never shown on the wall
